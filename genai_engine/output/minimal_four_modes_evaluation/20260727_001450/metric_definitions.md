# Metric Definitions for the PSQ-SCO Three-Layer Evaluation

## Evaluation Unit and Frequency

`120 cases` means 120 frozen input specifications, not 120 accepted scenarios. The design contains 30 base groups (`3 channels x 2 variants x 5 roles`), three difficulty anchors per group (90), and one balanced repetition per group (30). Each case is generated once in each of four conditions by each of three LLMs, yielding `120 x 4 x 3 = 1,440` finalized scenario rows in this run. The same case IDs make paired comparison possible even though the generated prose is expected to differ.

Row-level technical checks are calculated once for each finalized stored scenario after recovery/merge. Collection-level diversity is calculated once for each 120-row model-condition collection (12 collections). Condition summaries aggregate 360 rows. The experiment contains one stochastic generation replicate per model-case-condition cell, so random-seed variance cannot be estimated from the present run.

## Four Conditions

| Condition | Required name | Operational treatment |
|---:|---|---|
| 1 | Prompt-Only Generation | No external retrieval and no ontology-derived context. |
| 2 | Text-RAG Generation | Attempts external Chroma vector retrieval; actual context exposure is audited per row. |
| 3 | Ontology-Derived Structured Prompting RAG | Attempts external RAG and adds a directly serialized PSQ-SCO semantic packet. |
| 4 | Ontology-to-Text Vector RAG | Attempts external Chroma vector retrieval and adds ontology-derived text selected by a deterministic lexical ranker; actual external-context exposure is audited per row, and the ontology-derived records are not embedded by the current implementation. |

## Ground Truth and Reference Objects

There is no human-authored gold scenario in the current automatic evaluation. Three different reference objects must not be conflated: (1) the frozen case specification is the oracle for requested controls; (2) a method-invariant, automatically constructed closed-label case oracle supports concept P/R/F1; and (3) each RAG scenario has its own ordered retrieved context set for provenance. The combined corpus is never treated as a scenario-specific gold source. Human cybersecurity, pedagogy, usability, and ethical ratings remain required before a claim of final deployability.

## JSON Pass/Fail

A JSON row passes only when Python JSON parsing succeeds and the loaded row contains an inspectable `scenario` object. The reported mean is therefore an average binary pass rate. This check is applied to finalized stored objects after generation-engine parsing, repair, and recovery; it is not a raw-Ollama-output syntax rate.

## Scenario Decisions

The `technical_gate_v1` state machine is non-compensatory. Parse failure or a fired contradiction rule produces `REJECT_REGENERATE`. Missing game-executable fields, a critical control mismatch, two or more control failures, or two or more missing case concepts produces `MAJOR_REVISION`. One noncritical control mismatch or one missing case concept produces `MINOR_REVISION`. Only a row with none of these implemented defects is `ACCEPTED`. Automated acceptance means technical triage passed; every row still carries `final_human_review_required=true`.

## Source Mapping and Similarity

The correct mapping unit is one generated scenario to its own ordered context set, which can contain zero, one, or several documents. Retrieval relevance would require the scenario's retrieval query, ranked documents, scores/distances, and preferably human qrels. Generation faithfulness requires claim-level source mappings or entailment judgments. The frozen records do not preserve all of those fields, so the revised evaluator exports `NOT_ESTIMABLE_FROM_FROZEN_EXPORT` instead of inventing a source-similarity number. Source IDs measure traceability, not semantic support.

## Embedding Diversity

For collection embeddings `E_1...E_N`, `D_embed = 1 - [2/(N(N-1))] * sum_{i<j} cosine(E_i,E_j)`. The exact Sentence-Transformers model is frozen in run metadata and the result tables. It is computed within each 120-row model-condition collection. Higher values indicate greater relative dispersion under this representation; there is no universal acceptance threshold, and semantic distance is not content quality.

## Self-BLEU

`SelfBLEU = (1/N) * sum_i BLEU(x_i, X_{-i})`, where each scenario is the candidate once and the other scenarios in the same collection are references. It is computed within each 120-row model-condition collection. Lower is less lexical redundancy. It must be interpreted with semantic diversity and human inspection because low overlap can coexist with poor or incorrect text.

## Why Overall Conformance Can Be Below 1.0

The legacy conformance index falls below 1.0 when any of its five component values is below one: JSON object validity, control adherence, legacy method-conditioned concept F1, provenance-field completeness, or non-contradiction. Typical defects are missing provenance fields, missing closed case concepts, field/control mismatches, incomplete game schema, or contradiction rules. The revised decision state does not threshold this composite because its exact coefficients are uncalibrated and trace availability differs by condition.

## Optional BERTScore

BERTScore is not calculated in the standard publication profile and does not appear in its results.
